# AP 观众心景

把“这段为什么无聊、那个揭晓为什么有力量”变成可以检查、比较和被反馈纠正的创作假设。

工具根据作品中实际出现的线索，计算注意、惊、违和、理解推进、期待、压力、未闭合、疲劳等 **47 个状态通道**，以及 **19 类可配置的组合情绪**。这些通道包含认知感受、价值评价、运行状态和正负信号，不是声称发现了 47 种独立的人类基本感受。

**当前目标分数是指定艺术目标下的模型指数，不是观众满意率。** 群体预测是否有效，需要独立作品标注与真实观众数据检验。文稿、图像、视频、音乐可以使用同一计算框架，但输入线索需要人工或具有相应读片/听音能力的 Agent 标注；计算器本身不自动理解媒体。

## 最快开始

需要 Node.js 20 或更高版本，不需要 API Key。

```sh
git clone https://github.com/ginsonko/ap-aesthetics.git
cd ap-aesthetics
npm ci
npm run build
npm run serve
```

打开 **http://127.0.0.1:18933/**。也可以直接打开 `dist/ap-aesthetics.html` 离线使用计算器。原始作品、参数和反馈由你控制，工具没有自动上传行为。

## 让创作助手使用

```sh
npm run install:skill
codex mcp add ap-aesthetics -- node /仓库的绝对路径/bin/mcp.js
```

Windows 下可以把 `node` 换成 Node 的绝对路径。新会话可发现 Skill；MCP 是否需要刷新取决于客户端。

之后直接说：

> 用 $ap-aesthetics 评估这段漫剧。目标是先产生好奇，揭晓时温暖，结尾保留余韵。找出观众可能跟不上的地方，给出两个实际改稿，并在相同观众画像和参数下比较。保留可能的副作用。

Skill 会引导助手先读真实作品、按观众当时所知标注，再调用工具。没有看到线索的地方保留未知，不用导演已经知道的结局冒充观众先验。比较中不能只调高标注数字来宣称创作改善。

## 能做什么

| 能力 | 输出 |
| --- | --- |
| 作品评估 | 各阶段状态均值、峰值、结束值、多种并存情绪、正负来源与缺测 |
| 问题分析 | 可能缺少关系价值、加工负担过高、信息不发展、无意困惑的具体位置及多种改法 |
| 版本比较 | 同一观众、目标、参数下的变化，保留作品改动与模型变化的区别 |
| 观众画像对照 | 不同先验和敏感度下的情景估计；权重来自你给的假设，不冒充人口调查 |
| 参数微调 | 真实秒级状态演进的参数搜索；返回候选，不自动替换基线 |
| 输出标定 | 从独立人类观测拟合通道映射，报告留出误差和基线 |
| 可复现调用 | 10 个本地 MCP 工具、JSON CLI、可安装 Skill、单文件网页 |

CLI 示例：

```sh
node bin/cli.js evaluate examples/magi.json > evaluation.json
node bin/cli.js compare original.json revised.json > comparison.json
node bin/cli.js fit observations.json > candidate-model.json
```

详见 [模型与公式](docs/MODEL.md)、[独立标注说明](skills/ap-aesthetics/references/annotation.md)、[统计校准协议](docs/CALIBRATION.md)。

## 公开数据与群体建模

群体分布有可能比一个具体人的反应更稳定，因此可以检验“某类作品、某类观众、某一指标”的条件预测。稳定程度、文化差异与年代变化仍要测，不能预设为常数。

首版接入 EmoBank 的公开 VAD 数据，保存固定来源版本、许可和真实统计；它用于核对数据读取、分组、校准和报告是否工作。writer 与 reader 的评分不是 AP 输出，二者映射结果不能写成 AP 准确率。公开评论的作者情绪、作品表达的情绪、读者感到的情绪、喜欢程度也不能混用。

后续用独立作品线索标注产生 AP 预测，将观众评分作为单独标签；按作品/来源分组后，训练集拟合，验证集选择，测试集只报告。每个版本保留实际误差、未覆盖通道和不确定性。未知用 `null`，不补零；单个用户反馈用于定位问题，不代表人群统计。

## 两分钟体验

原 126 秒图解样片与互动反馈页保留在 `demo/`，用于复现技术流程。首次用户审阅认为画面与配音不足，目前正在完整重新创作，原版不能称为审美验收通过。先经历故事，在解释前留下自己的反应，再查看冻结预测；允许无感、猜到、反感、不同感受，也分别记录提示前后产生的怀疑。[制作与复现说明](docs/EXPERIENCE.md)。视频和语音文件默认不进 Git，源码和封面可复用。
